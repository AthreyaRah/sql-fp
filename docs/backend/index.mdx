# Backend Engineering

SQL as the storage layer behind an API. The database is the part of your service
that outlives every rewrite and is hardest to scale, so the queries an endpoint
runs — and the schema they run against — matter more than the framework around
them.

This track assumes [Foundations](/foundations/). It is being built out; the two
pages below are complete and set the format.

## Topics

1. [Keyset pagination & the N+1 problem](/backend/keyset-pagination-and-the-n-plus-1-problem)
   — why `OFFSET 100000` gets slower every page, the keyset fix, and the N+1
   query pattern ORMs fall into.
2. [Reading EXPLAIN plans & query optimization](/backend/reading-explain-plans-and-query-optimization)
   — the same endpoint query before and after an index, read off the plan node
   by node.

## On the build list

- Schema design for OLTP & normalization (1NF → BCNF), and when to stop
- Surrogate vs natural keys; `bigint` vs `UUID` vs `uuidv7`
- Modeling relationships: 1:1, 1:N, M:N, junction tables
- Soft deletes, `created_at`/`updated_at`, audit trails, triggers
- Optimistic vs pessimistic locking; `SELECT ... FOR UPDATE`
- Transaction anomalies in practice: lost update, write skew
- `EXISTS` vs `IN` vs `JOIN` for existence checks
- `JSONB`: when to reach for it, and `GIN` indexing
- Full-text search in Postgres: `tsvector`, `tsquery`, ranking
- Enums, lookup tables, and `CHECK` constraints
- Safe migrations: lock levels, backfills, `NOT VALID` constraints
- Idempotency keys & unique constraints for retried requests
- Connection pooling & prepared statements
