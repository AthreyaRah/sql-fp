# SQL from First Principles

Most SQL material teaches you syntax and hopes the model sticks. This teaches the
**model first** — what a relation actually is, what the query engine does with
your `SELECT`, why `NULL` breaks your `NOT IN`, what a B-tree buys you — and only
then the syntax, which by that point is obvious.

It is the sibling of
[Python from First Principles](https://github.com/AthreyaRah/python-fp), built the
same way: every claim is backed by a script that runs in CI, and every "this
breaks" is a script that really breaks.

## The three tracks

- **[Foundations](/foundations/)** — the SQL common core, in dependency order:
  the relational model, `NULL`, joins, aggregation, subqueries, CTEs, window
  functions, transactions, isolation, indexes, and reading query plans. Work
  top to bottom the first time.
- **[Backend Engineering](/backend/)** — SQL as the storage layer behind an API:
  keyset pagination, the N+1 problem, `EXPLAIN`-driven optimization, schema
  design, locking, JSONB, full-text search, safe migrations.
- **[Data Engineering](/data-engineering/)** — SQL as the transformation layer in
  a warehouse: dimensional modeling, slowly changing dimensions, incremental
  loads, deduplication, sessionization, partitioning.

## Why PostgreSQL

Everything targets **PostgreSQL** (the in-page engine is Postgres 16+; CI runs
every script on a stock Postgres 16). The concepts are standard SQL; Postgres
just has the clearest `EXPLAIN`, the fullest window-function and `MERGE` support,
and `GIN`/`BRIN`/partitioning for the later topics. If you use MySQL or SQLite,
95% transfers — the pages call out where it doesn't.
